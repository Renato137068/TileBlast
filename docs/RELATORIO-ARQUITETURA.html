De god-file a arquitetura modular

Refatoração staged e verificável do Tile Blast — modularização de CSS e JavaScript, centralização de configuração e documentação, com zero mudança de gameplay, UI, UX, animações ou balanceamento.

Projeto: Tile Blast Versão: 1.4.6 Estratégia: sem bundler · IIFE · namespace TB Testes: 87 verdes

Excelente — pronto para evoluir

Base significativamente mais organizada, testável e escalável. As extrações de maior risco (core do tabuleiro) foram deliberadamente deferidas por falta de cobertura unitária, com plano de continuação documentado.

📋 Resumo executivo

O que foi feito, por que, e o resultado.

🎯 Objetivo

Transformar um projeto centrado em um arquivo monolítico (HTML com ~630 linhas de CSS inline e ~4.800 de JS inline) em uma base modular, documentada e de fácil manutenção — sem alterar nada perceptível ao jogador.

🧭 Abordagem

Refatoração em estágios verificáveis. Cada estágio validado por Vitest + smoke no navegador. A extração de CSS foi conferida byte-a-byte (concatenação idêntica ao original) para garantir cascata inalterada.

✅ Resultado

3 novos módulos JS (TBConfig, TBAudio, TBUI), 12 módulos CSS, configuração centralizada, pipeline de build corrigido, documentação (ARCHITECTURE.md) e +9 testes.

🛡️ Garantias

Nenhuma regra, dificuldade, monetização ou animação foi tocada. Todos os call sites preservados via aliases. 87/87 testes verdes e boot validado no navegador em cada estágio.

🚀 Principais melhorias

Por estágio da refatoração.

Estágio 0 Configuração centralizada

Criado tb-config.js (window.TBConfig, congelado) reunindo números mágicos, thresholds de especiais, tabela de XP, recompensas, enums e chaves de save. O shell agora lê tudo de TBConfig, mantendo os mesmos nomes léxicos. Corrigido também o gap do minify-www.mjs (faltavam tb-meta.js e tb-juice.js).

Estágio 1 CSS modular

~630 linhas de CSS inline extraídas para 12 arquivos em css/, ligados por <link> na ordem exata da cascata original. <link> é render-blocking → sem FOUC. Precache offline e Capacitor atualizados.

Estágio 2 Áudio isolado

Sound e Haptic (feedback procedural, zero assets) movidos para tb-audio.js (window.TBAudio). Shell usa aliases const Sound = TBAudio.Sound. i18n já estava centralizado em tb-roadmap.js — um tb-i18n.js seria redundante (decisão documentada).

Estágio 3 Componentes de UI

Toast e Modal global centralizados em tb-ui.js (window.TBUI). Wrappers finos preservam showToast/showGlobalModal/closeGlobalModal — comportamento e acessibilidade (foco, aria) idênticos.

Estágio 4 Núcleo — decisão de risco

Extração física de board/hud deferida: forte acoplamento a globais do canvas e ausência de cobertura unitária. Em vez de arriscar regressão, adicionou-se cabeçalho arquitetural ao shell e plano de continuação. Modularizou-se primeiro o de baixo acoplamento.

Docs Documentação & convenções

Criado ARCHITECTURE.md (estrutura, módulos, dependências, ordem de carga, fluxo de boot, pipeline, checklist para novos módulos). Cabeçalhos padronizados em todos os módulos novos.

🏗️ Arquitetura

Namespace TB, sem bundler, IIFE por módulo.

🔗 Ordem de carregamento

tb-config→ tb-audio→ tb-ui→ tb-game-logic→ firebase/remote→ tb-roadmap→ tb-global→ features/push/meta/juice→ SHELL (gameplay)

O shell referencia TBConfig, TBAudio e TBUI logo no topo, então estes carregam antes.
