Veredito

A economia saiu de um estado inflacionário e descentralizado (nota ~28) para um sistema centralizado e tunável via TBEconomy + remote config. Compras passam a parecer atalhos convenientes; o jogador gratuito progride de forma viável, porém mais lenta.

📋 Resumo Executivo

Auditoria profunda + implementação de melhorias econômicas e estrutura LiveOps escalável.

Diagnóstico inicial

  • Moedas abundantes: missões + flash demo + ads + baús superavam sinks
  • Valores espalhados em tile_blast.html e tb-roadmap.js
  • coinMult no remote config existia mas não era aplicado nas vitórias
  • Loja estática, sem hierarquia clara de ofertas contextuais
  • Sem moeda premium (gemas) — apenas moedas soft, vidas, PUs e XP

Solução implementada

  • Novo módulo tb-economy.js como fonte única de dados econômicos
  • Rebalanceamento earn/spend (+25% moedas por estrela, sinks ajustados)
  • Multiplicador global: evento × remote × fim de semana (1,25×)
  • 7 pacotes IAP estruturados + oferta diária soft + ofertas dinâmicas
  • Esquema admin dashboard + calendário LiveOps documentado
Fair Play: Nenhuma mecânica de gameplay foi alterada. Boosters continuam opcionais; vidas e continue permanecem acessíveis via moedas, ads ou IAP — nunca obrigatórios para progredir.

💎 Gemas / Premium

Não existe moeda premium separada — decisão intencional para MVP. Moedas + IAP cobrem monetização. Estrutura em TBEconomy permite adicionar gems futuramente sem refactor.

❤️ Vidas

Max 5 · regen 30 min · grátis até nível 5 · ads + loja 70 💰. Padrão Royal Match. Escassez real pós-nível 20 sem punir excessivamente F2P.

⚡ Boosters

Shuffle, Bomba, Arco-íris, +5 Movimentos. Inventário + compra soft/IAP. Preços rebalanceados; oferta diária rotativa cria sink recorrente.

📺 Rewarded Ads

Implementação atual

  • Vida extra — opt-in na loja/perda
  • +50 moedas — limite 5/dia (remote tunável)
  • Continue — +5 movimentos via ad
  • Bônus login — estrutura preparada (+25 moedas pós-login)

Ads nunca interrompem gameplay — apenas botões explícitos. Interstitials separados com cap (5/dia, a cada 5 níveis).

Pendência crítica

IDs AdMob ainda são de teste Google. Receita real = 0 até configurar IDs de produção no Play Console + TileBlastBridge.java.
