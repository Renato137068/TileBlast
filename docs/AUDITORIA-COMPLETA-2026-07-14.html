Notas por categoria

Testes & QA 85

195 testes (unit + integração + e2e Puppeteer), todos verdes em 5,8s. CI no GitHub Actions com job unit/boot e e2e-smoke. Falta relatório de cobertura (%) configurado.

Acessibilidade 90

ARIA extensivo, regiões aria-live, sr-only, skip-link, modo daltônico, "reduzir animações", a11y.css dedicado e canvas com instruções de teclado. Referência para jogos mobile.

Documentação 88

ARCHITECTURE.md é "documento vivo" validado por teste de integração. Diversos relatórios temáticos (economia, game-feel, performance). Muito acima do típico.

Build / DevOps 85

Bundle concatenado (18→1), minificação, Capacitor Android, geração de ícones/assets Play Store, pipeline play:release. Higiene de segredos correta (keystore/firebase no .gitignore).

Performance / PWA 85

Canvas + requestAnimationFrame, service worker com precache offline, manifest completo (maskable, display_override), preload/preconnect e fonte carregada de forma diferida.

Qualidade de Código 75

Prettier + ESLint (gate no-undef sobre bundle concatenado) limpos, zero marcadores de débito. tb-game-logic.js é lógica pura, testável e bem comentada. Puxado para baixo pelos monólitos.

Arquitetura 72

Modularização por globais window.TB* com ordem de carga como fonte única da verdade (validada por teste). Boa ideia, mas tb-main.js (7.243 linhas) e tb-roadmap.js (~117 KB) concentram responsabilidade demais.

Segurança 70

Escape de HTML disciplinado (_escTB/escapeHtml), assinatura de save (deterrent honesto e documentado), segredos fora do repo. Falta CSP; economia é client-trust; innerHTML via template exige vigilância contínua.

Manutenibilidade 68

Estado mutável compartilhado no realm global (lvIdx, LEVELS, isInfiniteMode…) acopla os módulos satélites ao tb-main.js. Sem TypeScript, refatorar 250 KB de JS é arriscado. Testes mitigam parte do risco.

Produto / Game Design 85

Conjunto de features amplo e coerente: 60 fases + mundos, puzzle diário global, modo infinito/tempo, passe de batalha, eventos, missões, meta (jardim), skins, i18n pt/en/es, loja com IAP e recompensa por anúncio.

✅ Pontos fortes

  • Testes reais e verdes: 195 casos, incl. e2e de gameplay/vitória/derrota/mapa.
  • CI/CD: GitHub Actions roda unit + e2e a cada push/PR.
  • Lógica pura isolada: tb-game-logic.js — flood-fill, pontuação, regeneração de vidas, RNG determinístico (mulberry32) por seed.
  • Segurança de segredos: keystore, firebase-config.js e senhas no .gitignore; só placeholders versionados.
  • Anti-tamper honesto: tb-secure.js assina o save e documenta explicitamente que é deterrent, não garantia criptográfica.
  • Acessibilidade de primeira linha e PWA offline completo.
  • Zero débito sinalizado (nenhum TODO/FIXME/HACK) e lint limpo.

⚠️ Riscos & recomendações

  • ALTA Quebrar tb-main.js (7.243 linhas / 270 funções). Extrair módulos por domínio (loja, mapa, HUD, resultado). É o maior risco de manutenção.
  • MÉDIA Adicionar Content-Security-Policy (meta ou header) para blindar as ~41 escritas de innerHTML.
  • MÉDIA Reduzir estado global mutável (lvIdx, LEVELS…). Encapsular num objeto de estado único injeta testabilidade.
  • MÉDIA Validação server-side da economia se moedas/IAP virarem alvo de fraude (hoje é client-trust).
  • BAIXA Configurar cobertura (vitest --coverage) e publicar % no CI.
  • BAIXA Migrar onclick inline do HTML para listeners (melhora CSP e separação de responsabilidades).
  • BAIXA Avaliar JSDoc/TypeScript incremental ou // @ts-check nos módulos puros para segurança de tipos sem reescrever tudo.
